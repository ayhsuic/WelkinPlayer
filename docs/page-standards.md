# 后续页面标准规范（以首页为基准）

## 1. 定位与分工

首页 `LibraryView` 已定稿，作为全站视觉与尺寸基准。本规范规定其他页面必须沿用的底座、骨架、组件复用与禁忌；首页各卡片/条目的具体档位系数见 `home-scale-model.md`，此处不重复抄录。

目标：跨页保持一致的边距、字号、卡片切角、列表与网格手感；新页面不另起一套尺寸口径，也不引入第二套色板或切角样式。

纳入：乐库/分类列表、搜索、源浏览与源配置、收藏、歌单、下载、设置、各类编辑与信息页。
不在本规范：封面墙晶格布局、全屏播放页与歌词页、墙面侧进度条（维持各自现有约束）。

## 2. 统一底座（继承，不要重定义）

### 2.1 预算基准变量

变量由 `src/App.vue` 注入，页面直接 `var(--cw)/var(--ch)/var(--rail-scale)` 读取，不要在页面内另算宽高基准。

| 变量 | 含义 | 取值 |
|---|---|---|
| `--cw` | 宽度预算基准 | 竖屏 = 视口宽；横屏 = 侧栏宽 `navWidth` |
| `--ch` | 高度预算基准 | 横竖屏都 = 容器可视高；`:root` 兜底 `100vh` |
| `--rail-scale` | 二次缩放系数 k | 恒为 `1`；样式侧统一 `var(--rail-scale, 1)` 兜底，变量位保留以备后用 |

`watchEffect` 把三个变量同步到 `documentElement`，Teleport 到 body 的抽屉/弹层也能继承；横屏 aside 再覆盖一次 `--cw`。页面不要在 Teleport 边界外自己重算基准。

### 2.2 色板

文字、边框、背景、强调色只取下列 CSS 变量，不写死十六进制颜色（暗色与各强调色主题由 `:root` / `.dark` / `html[data-accent]` 切换）。

| 变量 | 用途 |
|---|---|
| `--bg` | 页面底色 |
| `--surface` / `--elevated` | 卡片/抬升面 |
| `--fg` | 主文字 |
| `--muted` | 次要文字 |
| `--dim` | 弱化/计数文字 |
| `--line` / `--line-strong` | 常规分隔线 / 加强分隔线 |
| `--accent` / `--accent-fg` / `--accent-soft` | 强调色、强调色上的文字、强调色柔底 |

### 2.3 切角与高亮层体系

切角、描边、悬停/选中态复用 `style.css` 里的 `ak-` 体系，不要自写 clip-path 或描边。

| 类 | 用途 |
|---|---|
| `.ak-frame` | 方形占位/图标框，带 L 形强调色描边（左上、右下两段） |
| `.ak-clip` | 双角切角矩形（左上、右下切角） |
| `.ak-clip-tr` | 右上、右下切角矩形（封面/卡片常用） |
| `.ak-select` | 选中高亮层：强调色底 + 切角蒙版，白色文字 |
| `.ak-hover` | 悬停高亮层，`::before` 覆盖在内容之下 |

## 3. 尺寸口径（高度优先，三限制）

### 3.1 写法约定

- **高度优先**：方卡/横条先把 `height` 锚到 `--ch` 的固定比例，再用 `aspect-ratio` 由高度反推宽度；宽度不作为起步预算，也不靠高度封顶回压宽度。宽侧栏把容器拉宽时，条目不被拉成超宽扁条。
- **三限制**：宽度走百分比预算、形态锁固定比例、高度设上限；三者共同约束单个元素。
- 方卡：`height: ch×比例×k` + `aspect-ratio: 1/1`，宽度反推，`max-width: 100%` 兜底防窄屏溢出。
- 横条条目：`height: ch×比例×k` + `aspect-ratio` 反推宽度，`min-width: 0`，标题在宽度内截断。
- 封面：`height` 锚定所属条目/卡片高度，`aspect-ratio: 1/1`，宽度反推。
- 网格墙是唯一列宽驱动：封面宽跟随网格列宽，高度由 `aspect-square` 反推，再用 `max-height/max-width` 封顶到推荐卡边。

### 3.2 间距与字号档位

页面内间距、字号优先复用首页已定稿的档位（系数明细见 `home-scale-model.md` 第 3.3、3.4 节），不要在新页面另设一档：

- 横向间距 `.home-gap-x`、行/卡间距 `.home-gap-row`、网格列距/行距 `.home-gap-y-grid`；
- 段间距 `.home-mt-section`、卡间距 `.home-mt-card`、标题下距 `.home-mb-title`、副标题上距 `.home-mt-caption`、列表底距 `.home-pb-rail`；
- 卡片标题/歌手、网格标题/歌手字号走 `min(cw×系数, ch×系数)×k` 的双预算取小写法。

## 4. 页面骨架标准

- **外层滚动**：页面根节点 `h-full w-full overflow-y-auto`，纵向滚动由页面自身或传入的共享 scroller 承接；不要在页面内再套一层无约束的横向溢出容器。
- **内容区**：`mx-auto` 限宽居中，纵向节奏用段间距/卡间距档位；左右边距对齐首页内容边，不贴屏幕边。
- **页头**：标题 + 副标题/计数 + 操作按钮组；封面/图标占位用 `.ak-frame` 方标；主操作按钮用 `.ak-clip-tr` 强调色切角按钮，次操作走边框按钮。
- **内容区**：列表/网格直接接复用组件（第 5 节），不在页面模板里自造行式列网格或封面墙排版。

## 5. 复用组件优先

页面内容优先复用 `src/components/` 现有组件，保持行高、列网格、封面比例、菜单行为与首页一致。

| 组件 | 用途 | 接线要点 |
|---|---|---|
| `TrackList` | 行式列表（默认列表形态） | 纵向虚拟化；移动端/宽屏两套列网格；接入字母索引、多选、移除；`scroller` 传入外部滚动容器 |
| `TrackCard` | 网格封面卡 | 封面 1:1 + 标题/歌手槽；悬停出播放钮，当前曲带均衡器徽标 |
| `TrackContextMenu` | 曲目右键/长按菜单 | 页面持有 `contextTrack` 与 `contextPosition`，菜单事件回传曲目与坐标 |
| `TrackSortMenu` | 排序菜单 | 接 `useTrackSort` 的 key/dir；选项默认/标题/艺人/专辑 |
| `ViewModeToggle` | 列表 ↔ 网格切换 | 视图模式本地持久化（`trackViewMode`） |
| `TrackIndexRail` | A–Z 字母索引侧栏 | 仅标题排序且非多选时显示；`select` 事件定位到条目 |
| `CacheBadge` | 缓存/下载状态标记 | 按 `trackKey` 判定缓存态 |

事件约定与首页一致：`play`（在队列内播放）、`menu`（打开上下文菜单）、`openArtist`、`openAlbum`、`remove`（可移除列表）；曲目不可用时置灰、不参与排队与播放。

## 6. 横滑与虚拟化手感

页面内出现横向卡流（露头卡、折列、横滑小卡）时，沿用首页口径：

- 自滚横向宿主必须定高，否则虚拟化容器交叉轴塌缩；条目间距并入槽宽（项宽 + 间距），由虚拟化按槽宽排布，不用容器 `gap` 补横向间距。
- **末项不带尾部间距**：最后一列/卡用纯项宽，不留尾部死槽；否则这段空白在 `mandatory` 吸附下会成为独立吸附位，把静止位置拉偏。
- 手势：横向宿主 `touch-action: pan-x`，带 `-webkit-overflow-scrolling: touch`；卡流 `scroll-snap-type: x proximity` 就近吸附，折列 `x mandatory` 按列分页，子项/列 `scroll-snap-align: start`。
- 祖先纵向滚动体（抽屉内容层、横屏侧栏）`touch-action: pan-x pan-y`，不要锁成 `pan-y`，否则手势交集会锁死后代横滑。
- 纵向长列表走 `VList`/`Virtualizer` 纵向虚拟化，复用共享 scroller 并带 `start-margin`；条目全量参与，不做条数截断。

## 7. 固定像素保留件

下列跨页装饰与通用部件维持固定 px，不纳入 `--cw/--ch` 预算：

- 切角 `--cut: 12px`、L 形描边 `1/2px`、clip-path 切角、均衡器条（12px / gap 2px）、阴影；
- 弹窗/开关/通用小部件：开关 `46×24`、底栏避让 `84px`、子面板 `min(340px, 100%-80px)`、弹层 `bottom 24px`、抽屉把手 `HANDLE_W = 18px`。

## 8. 禁忌

- 不在新页面写死卡片宽高、字号 px；不走「宽度预算起步 + 高度封顶回压」的旧口径。
- 不引入第二套色板、第二套切角/描边样式；颜色只取第 2.2 节变量。
- 横向宿主不锁纵向轴导致横滑失效；祖先不把 `touch-action` 锁成 `pan-y`。
- 不对列表做条数截断；溢出交给虚拟化承接。
- 不在页面模板里重复实现 TrackList/TrackCard 已有的行网格、封面比例、菜单与徽标逻辑。

## 9. 落地与验收

1. 类型检查：`node node_modules/vue-tsc/bin/vue-tsc.js --noEmit`，退出码 0。
2. 前端构建：`node node_modules/vite/bin/vite.js build`，退出码 0（chunk 体积警告除外）。
3. 两档视口抽查：9:21 竖屏与 21:9 横屏，条目比例正确、无横向溢出、封面不拉扁、末项无尾部死槽。
4. 复用组件事件接通：播放、上下文菜单、排序、多选/移除、字母索引可用。
5. 过程截图归档到 `_ui_check/`（已在 `.gitignore`，不入库）。

## 10. 现状待收口

现有部分二级页面仍保留 Tailwind 固定 px（页头方标、标题字号、列表行高等）。新页面按本规范走预算口径，不要复制这些固定值；旧页面随后续改造逐步收口，不在新页面里回退到写死像素。
